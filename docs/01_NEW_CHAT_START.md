## Запуск и проверки

В одном окне PowerShell запустите сервер:

```powershell
.\start-local.ps1
```

Во втором окне из корня проекта:

```powershell
node scripts/check-project.cjs --http http://127.0.0.1:4173/
node scripts/verify-works-static.cjs
node scripts/verify-services-static.cjs
node scripts/check-hero-geometry.cjs
node --test scripts/test-static-checks.cjs
git ls-files --cached --others --exclude-standard | node scripts/check-doc-links.cjs
```

Для браузерных проверок нужны Playwright и подходящие браузеры. Укажите порт той копии, которую проверяете:

```powershell
$env:SYNTHECORE_URL = 'http://127.0.0.1:4173/'
node scripts/verify-v60-regressions.cjs
node scripts/verify-v60-browser.cjs
```

Без этой переменной браузерные сценарии используют порт 4174. В новом сеансе проверьте доступность сервера. Результат предыдущего запуска не подтверждает состояние после новых изменений.

## Что важно сохранить

Единственный владелец плавной прокрутки Lenis — `js/hero-scroll.js`. Works использует одну закреплённую GSAP-сцену, Services — горизонтальную сцену с обычной лентой на малых экранах. Отзывы сохраняют согласованную механику v58: CSS sticky и движение карточек по прокрутке, отдельного GSAP pin у них нет. Подробные условия и пересчёт размеров описаны в технических документах.

Сохраняйте согласованные тексты, порядок разделов, изображения и механику анимаций. Подтверждённый дефект сначала воспроизведите, затем исправьте и повторите проверку на проблемном и соседних размерах.

`.gitattributes` сохраняет точные байты SVG и библиотек, чтобы Windows не менял контрольные суммы файлов. Не удаляйте эти правила, manifest-файлы, историю Git и `backup/`.

## Ограничения и история

Отзывы и портреты демонстрационные. Для публикации нужны реальные материалы либо согласованное скрытие раздела; FAQ и контакты требуют подтверждения. Не добавляйте вымышленные отзывы, обещания и результаты проверок. Публикация требует отдельного поручения владельца.

Документы v31 и промежуточных версий — история своих итераций. Их старые результаты не переносятся на новый код. Назначение текущих и старых сценариев указано в [реестре проверок](../scripts/HISTORICAL_CHECKS.md). Пути к отсутствующим preview и видео обозначают локальные материалы, а не файлы, которые обязательно будут в клоне.
