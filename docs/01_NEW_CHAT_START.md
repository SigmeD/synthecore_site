# Старт нового чата — SyntheCore v31

Сначала прочитайте [README](../README.md), [архитектуру](SITE_ARCHITECTURE.md), [механику прокрутки](SCROLL_MECHANICS.md), [CSS-каскад](CSS_CASCADE_V31.md) и [QA v31](QA_V31.md). Они описывают текущую страницу. [Мастер-контекст](00_MASTER_CONTEXT.md), старые планы и отчёты сохраняют историю; их формулировки «актуально» и «проверено» относятся к датам соответствующих итераций.

Принятая база: `038a062f95b52f833910aa99a12e2364b8460d97`, merge PR #1 с интеграцией Works v31. Рефакторинг ведётся отдельно в `refactor/site-css-js-docs-v31`. Принятие интеграции не означает автоматическое принятие последующих изменений.

Текущий порядок: Hero → «С кем работаем» → Works (b2b, flowers, crm, beauty, prostor, metal) → заглушка будущих услуг → контактный footer с почтой. Не возвращайте старые заглушки Works/контактов. Сохраняйте HTML-тексты и статусы концептов/прототипов, изображения, типографику, композицию, порядок секций и карточек.

Исходники: `index.html`, `css/main.css`, `css/works.css`, `js/hero-geometry.js`, `js/hero-scroll.js`, `js/main.js`, `js/works.js`. Локальные библиотеки — GSAP/ScrollTrigger 3.12.5 и Lenis 1.3.26. Lenis создаётся только в Hero-контроллере и получает время от одного GSAP ticker. В текущем коде нет wheel-gate или требования отдельного жеста после раскрытия. Works создаёт шесть отдельных tween/ScrollTrigger, sticky задан CSS.

Из PowerShell запустите `.\start-local.ps1` либо `start-local.bat`; по умолчанию адрес `http://127.0.0.1:4173/`. В новом сеансе перепроверьте сервер и браузер: исторические сообщения об их доступности ничего не гарантируют. Для сайта установка пакетов не нужна. Текущие Node-проверки:

```powershell
node scripts/check-project.cjs
node scripts/verify-works-static.cjs
node scripts/check-hero-geometry.cjs
```

Для сравнения в браузере используйте `node scripts/verify-v31-browser.cjs --capture=before` и `--capture=after`; адрес можно изменить через `SYNTHECORE_URL`. Условия запуска, фактические результаты и границы проверки находятся в QA. При изменениях движения проверяйте реальную прокрутку, reverse, якоря, resize и reduced motion; статические проверки не подтверждают визуальную приёмку.

Исторические `output/`-пути — локальные артефакты, обычно отсутствующие в Git. Не добавляйте на них кликабельные ссылки и не выдавайте старые отчёты за новые проверки. Не выдумывайте клиентов, коммерческие кейсы, отзывы, показатели или результаты QA. Сохраняйте `backup/` и manifest-файлы. JS-алгоритмы меняйте только при воспроизводимом дефекте с отдельной проверкой.
