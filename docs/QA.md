# Проверки сайта

Здесь собраны команды для действующей v62 с оболочкой и каталогом v27. Сохранённый успешный отчёт относится к своей сборке: после новой правки проверку нужно повторить по её области влияния.

## Проверка без браузера

Нужны Node.js и Git. Выполняйте из корня проекта:

```powershell
node scripts/verify-site.cjs --git-ref HEAD
```

Команда проверяет сборку HTML/CSS, сохранность анимаций, шаблоны, ресурсы, структуру разделов, геометрию, все `test-*.cjs` и ссылки документации. До коммита сначала подготовьте файлы через `git add`, затем запустите без `--git-ref HEAD`: будет проверен индекс. Отдельные команды остаются доступны в [карте scripts](../scripts/README.md). Названия v60/v61 в сообщениях унаследованы из разработки и не предлагают вернуть старую версию сайта.

При работающем сервере проверьте, что он отдаёт текущие файлы:

```powershell
node scripts/verify-site.cjs --git-ref HEAD --http http://127.0.0.1:4176/
```

Замените порт, если сервер запущен по другому адресу.

## Что сравнивают контрольные суммы

26 октября для Get Started разрешена точная замена `href` CTA обсуждения задачи. [Исключение CTA](../scripts/lib/approved-discussion-links.cjs) восстанавливает только зарегистрированные открывающие теги ссылок на старых страницах и в пяти исходных HTML перед прежними SHA-проверками. Неверные URL, дубли, изменение текста, SVG, положения и атрибутов проверяются отрицательными тестами; отдельный тест использует временный Git index. Обычные email и новые маршруты не преобразуются. Исходные manifests и все 17 motion SHA неизменны.

23 октября по заданию на рефакторинг главная получает один сгенерированный CSS вместо 18 тегов. Проверка восстанавливает только точный утверждённый блок подключений перед прежним сравнением HTML. Сам артефакт проверяется пересборкой из исходных blobs того же Git index/коммита; подмена файла на диске не скрывает ошибку в Git. Исходные manifests и все 27 модульных CSS остаются прежними. [Аудит](REFACTOR_AUDIT.md) и [результаты сравнения](qa/style-scripts-refactor/README.md).

| Манифест | Что защищает |
|---|---|
| [V62_SOURCE_SHA256.json](V62_SOURCE_SHA256.json), раздел `motion_lock` | 17 файлов анимаций v62, побайтно |
| [V62_ON_V27_SOURCES.json](V62_ON_V27_SOURCES.json) | Те же 17 файлов, 25 исходников оболочки/каталога v27 и полный фрагмент семи секций главной |
| [asset-manifest.json](asset-manifest.json), [vendor-manifest.json](vendor-manifest.json), [font-manifest.json](font-manifest.json) | Изображения, библиотеки и локальные шрифты |

`verify-v62-import.cjs` проверяет файлы на диске. `verify-git.cjs HEAD` проверяет содержимое последнего коммита; без `HEAD` — подготовленные к коммиту файлы в индексе. Проверка коммита не видит незакоммиченные изменения.

Для 17 файлов важны даже окончания строк LF/CRLF. При checkout и staging этих файлов используйте `core.autocrlf=false`. Для текстов v27 и секций HTML проверка отдельно нормализует окончания строк; бинарные шрифты проверяет без преобразований.

21 октября владелец утвердил новые названия и две плашки карточек каталога после просмотра локального варианта. Исходные манифесты не изменены. Для двух HTML-файлов каталога проверка сначала отменяет только точные согласованные текстовые замены, затем сравнивает результат с прежним SHA v27. Другой текст, структура, хедер, футер, стили и скрипты по-прежнему защищены. Новые названия главной страницы в эту задачу не входят.

22 октября владелец поручил убрать свечение только оранжевых кнопок во всём сайте. Для сравнения с исходными SHA v27 [точное исключение](../scripts/lib/approved-button-shadows.cjs) удаляет только две добавленные строки токенов из `design-tokens.css` и один импорт `button-interactions.css` из `shared-header-cta.css`. Изменение прочих правил, дублирование или подмена добавлений отклоняются. Все 17 motion-файлов, исходные манифесты, HTML-секции, partial-файлы и остальные исходники v27 проверяются по прежнему контракту.

23 октября для готовых кейсов утверждены основные прямые переходы. [Исключение ссылок](../scripts/lib/approved-case-links.cjs) восстанавливает только точные ссылки зарегистрированных JSON-кейсов и единственную замену модального селектора на `button.case-card__open`. Геометрия и тексты сохраняются; overlay главной должен покрывать весь frame. Подмена URL, перенос внутрь текстовой плашки или Header/Footer и дубли отклоняются тестами. Это дополнение к прежнему контракту, исходные manifests и 17 raw motion SHA не меняются.

Проверка кнопок в Chromium при запущенном локальном сервере:

```powershell
node scripts/verify-orange-buttons.cjs
```

Сценарий использует существующую локальную установку Playwright. Он проверяет главную и каталог на 320/390/768/1024/1440 px: обычное состояние, hover, удержание мыши, клавиатурный Tab и outline, мобильное меню, шаги процесса, карусель услуг, проектные диалоги и горизонтальную прокрутку. Локальные отчёты и снимки кнопок сохраняются в `output/playwright/orange-buttons/`. Для сравнения геометрии, шрифтов, цветов, стрелок и остальных теней нужен `baseline.json`, снятый командой `node scripts/verify-orange-buttons.cjs --baseline` **до изменения CSS**. На исходной версии проверки отсутствия свечения ожидаемо завершаются ошибкой. Без baseline сценарий проверяет текущее поведение и сообщает об отсутствии сравнения с исходником; такой запуск не заменяет сравнение до/после.

## Проверка в браузере

Нужны Playwright и установленный Chromium. Это инструменты проверки, сайт от них не зависит. Сценарии ищут пакет Playwright в проекте либо в профиле пользователя.

Сначала запустите сервер в отдельном терминале:

```powershell
.\start-local.ps1 -Port 4176 -NoBrowser
```

В другом терминале из корня проекта выполните:

```powershell
$env:SYNTHECORE_URL = 'http://127.0.0.1:4176/'
node docs/qa/v62-on-v27/catalog.cjs
```

Сценарий проверяет главную и каталог: меню, размеры, диалоги, фокус, футер, режим уменьшенного движения и одного владельца прокрутки. Результат появится в `output/v62-on-v27/catalog/`. Новый запуск может заменить предыдущие локальные результаты.

После изменений страницы дополнительно просмотрите desktop и mobile: начало и конец разделов, быстрый скролл вниз, обратный скролл вверх, изменение ширины, меню и диалоги. Плавность физической мышью или тачпадом оценивается вручную; автоматические события браузера её не доказывают. Если проблема затрагивает замороженную анимацию, передайте её владельцу.

## Сравнение с эталонами

Полные сценарии [motion.cjs](qa/v62-on-v27/motion.cjs) и [shell.cjs](qa/v62-on-v27/shell.cjs) требуют исходных сборок. Они используют фиксированные адреса; `SYNTHECORE_URL` на них не влияет.

| Порт | Каталог относительно корня проекта | Содержимое |
|---|---|---|
| 4180 | `output/worktrees/works-v27` | v27 из коммита `0849711` |
| 4181 | `.` | Текущая сборка |
| 4182 | `output/v62-source` | Оригинальный архив v62; `index.html` лежит прямо в этом каталоге |

Эталоны и ZIP не входят в новый клон. Не перезаписывайте существующие папки: сначала проверьте `git worktree list` и их содержимое. Коммит v27 доступен в истории main. SHA-256 исходного ZIP: `2169bdac56210c3d5f4874b1147be0b2bf6958f14af941d175589502be9e7b0a`.

Когда эталоны готовы и порты свободны, запустите в отдельном терминале:

```powershell
node docs/qa/v62-on-v27/serve.cjs
```

Затем выполните:

```powershell
node docs/qa/v62-on-v27/motion.cjs
node docs/qa/v62-on-v27/shell.cjs
```
