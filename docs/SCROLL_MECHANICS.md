# Как работают анимации

Это описание принятой v62, а не список настроек для изменения. Анимации, хедер и футер заморожены. Если обнаружена проблема, зафиксируйте её и передайте владельцу. [Проверки](QA.md), [правила](../AGENTS.md).

## Прокрутка страницы

На главной `hero-scroll.js` создаёт один Lenis для плавной прокрутки. GSAP передаёт ему время, а ScrollTrigger получает положение страницы. Для главной сохранён `lerp:0.068`. Даже когда Hero на телефоне работает без анимации, общий Lenis остаётся. При включённом уменьшении движения он отключается.

Каталог — отдельная страница. Его прокруткой управляет `raboty-scroll.js` с исходными настройками v27: `duration:1.2`, `lerp:0`. Подключать оба владельца к одной странице нельзя.

Главная использует общий `SyntheCoreMotion` для переходов и пересчёта размеров. Запросы пересчёта объединяются; во время плавной прокрутки измерение откладывается до подходящего момента. Вторая независимая прокрутка поверх Lenis не нужна.

## Поведение разделов

| Раздел | Что происходит |
|---|---|
| Hero | Фотография раскрывается и увеличивается. Секция удерживается CSS sticky; следующий текст появляется у конца сцены |
| Наши работы | Первая карточка плавно растёт при входе. Затем следующие карточки поднимаются и увеличиваются, перекрывая предыдущие |
| Что мы делаем | На подходящем desktop-экране вертикальная прокрутка двигает карточки горизонтально. Первая карточка на старте выровнена с заголовком |
| Шаги | Hover и фокус подсвечивают шаг; click или tap сохраняет выбор |
| Отзывы | Четыре ДЕМО-карточки движутся единым потоком. Дистанция увеличена на 30%, последняя карточка остаётся видимой при выходе |
| FAQ | Открыт один ответ. После изменения высоты раздел запрашивает общий пересчёт |

Hero, работы и услуги закрепляются через **CSS sticky**, без прежних GSAP pin-spacer. Слова `pin` в именах диагностических полей не означают, что включён GSAP `pin:true`.

На узких экранах услуги остаются горизонтальной лентой с обычным swipe. Нативные режимы Hero, услуг и отзывов включаются по их собственным условиям. Узкая ширина сама по себе не отключает анимацию работ. Режим уменьшенного движения учитывается отдельно.

## Контрольные параметры для диагностики

Эти значения нужны, чтобы распознать принятую реализацию и не спутать её со старой.

| Сцена | Значения из исходников |
|---|---|
| Hero | Диапазон `round(innerHeight * 1.1)`, `scrub:true`, раскрытие на всём диапазоне. Compact-условие: ширина до 850px либо aspect ratio от 3:1; также учитывается указатель |
| Вход первой работы | От `top bottom` до `top top`, scale `.885 → 1`; до 480px — `.9 → 1`, ease `none` |
| Следующие работы | Пять переходов общей длиной `round(5 * innerHeight * .92)`, `scrub:true`, увеличение с `sine.inOut` |
| Услуги | Desktop от 851px шириной и 650px высотой. Смещение — разность ширины track и viewport; дистанция `max(250, round(travel * 1.08))`, `scrub:true` |
| Старт услуг | В sticky-режиме viewport имеет `overflow:clip`, `scrollLeft:0`; лента перемещается transform |
| Отзывы | От 1200×800, высота `533svh`, минимум 3770px; сглаживание `0.18s`, без GSAP pin |
| FAQ | Запрос пересчёта после 120ms без новых изменений высоты |

У Hero измеряйте видимую область фотографии и вложенное изображение: размеры внешнего контейнера не показывают её раскрытие. Не удаляйте скрытую `.photo-caption` и другие узлы, к которым обращается код.

## Меню и футер

Меню главной обслуживает защищённый `main.js`, меню каталога — `site-header.js`. Оба обработчика одновременно не подключаются.

Футер общий для двух страниц. `footer-waves.js` рисует три слоя волн со скоростями `.50/.60/.70`; вне экрана, в скрытой вкладке и при уменьшении движения они останавливаются. `footer-reveal.js` показывает CTA с scale `.8 → 1` за `.92s`, нижнюю навигацию и copyright — с fade `2.55s`. Эти эффекты сохранены из v27.

В защищённом `faq-footer.js` осталась старая ветка волн, но в новом футере нет её DOM-узлов. Удалять эту ветку ради уборки кода нельзя: файл защищён целиком.
