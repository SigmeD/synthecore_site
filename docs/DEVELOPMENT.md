# Работа с проектом

SyntheCore — статический сайт. Для просмотра не нужны установка npm-пакетов или сборка приложения. В репозитории уже есть HTML, изображения и библиотеки.

## Как запустить

Откройте терминал в `D:\Projects\synthecore` и выполните:

```powershell
.\start-local.ps1
```

Можно также открыть `start-local.bat`. По умолчанию сайт доступен на `http://127.0.0.1:4173/`, каталог — на `/raboty/`. Остановка сервера — Ctrl+C в его терминале.

В текущем сеансе для основной копии выбран порт 4176:

```powershell
.\start-local.ps1 -Port 4176 -NoBrowser
```

Адрес: `http://127.0.0.1:4176/`. В новом сеансе сначала убедитесь, что сервер запущен. Порты 4180–4182 используются отдельно для сравнения с эталонами, см. [QA](QA.md).

## Где что лежит

| Папка или файл | Назначение |
|---|---|
| `templates/pages/home.html` | Шаблон главной страницы |
| `templates/pages/works.html` | Шаблон каталога работ |
| `templates/pages/case.html`, `templates/data/cases/` | Единый шаблон детальных работ v20 и фактические данные |
| `templates/partials/` | Общие хедер и футер |
| `index.html`, `raboty/index.html` | Готовые страницы для просмотра и публикации |

| `assets/` | Изображения, SVG, шрифты и локальные библиотеки |
| `scripts/` | Сборка и автоматические проверки |
| `docs/qa/v62-on-v27/` | Сохранённые доказательства приёмки |
| `output/` | Локальные результаты и эталоны; целиком в Git не отправляются |

Если задача разрешает изменение страницы, правьте шаблон, затем выполните `node scripts/build-site.cjs`. Шаблон и готовый HTML должны попасть в один коммит. Команда `node scripts/build-site.cjs --check` только проверяет их совпадение и ничего не записывает.

Детальная страница доступна по `/raboty/beauty-insight/`. Остальные кейсы создаются заменой подтверждённых данных и изображений в том же шаблоне. Структура, ограничения и порядок наполнения описаны в [шаблоне v20](CASE_TEMPLATE_V20.md).

## Как устроена текущая сборка

Главная содержит семь секций из утверждённой v62: Hero, аудитории, работы, услуги, шаги, отзывы и FAQ. Хедер, футер и каталог сохранены из согласованной v27. Общая разметка хедера и футера берётся из одних partial-файлов.

Стили главной подключаются в таком порядке: базовые файлы разделов, надстройки v62, общие стили v27 и `v62-v27-shell-preservation.css`. Последний файл восстанавливает согласованный вид хедера и футера после общих правил v62. Применять его к остальным секциям нельзя.

Главная управляет прокруткой через `hero-scroll.js`, меню — через защищённый `main.js`. В каталоге используются `raboty-scroll.js` и `site-header.js`. Это две разные страницы; второй обработчик меню или прокрутки на одну страницу подключать нельзя. На обеих страницах волнами и появлением футера управляют `footer-waves.js` и `footer-reveal.js`.

Токены общих компонентов находятся в `css/design-tokens.css`. Они описывают оболочку и каталог, но не заменяют стили всех секций главной. Параметры [анимаций](SCROLL_MECHANICS.md), типографику и отступы не нужно унифицировать без задания.

### Кнопки в дизайн-системе

Правило для оранжевых кнопок: **кнопки не используют свечение и усиление теней при взаимодействии**. Общие токены в [design-tokens.css](../css/design-tokens.css):

```css
--sc-button-shadow: none;
--sc-button-hover-shadow: none;
```

[button-interactions.css](../css/button-interactions.css) — общий компонентный слой, подключённый из `shared-header-cta.css` на обеих страницах. Он применяет токены в обычном состоянии и при `hover`, `focus-visible`, `active` к CTA главной, каталога, мобильного меню, футера и проектных диалогов, а также к активному оранжевому шагу процесса. Для новых оранжевых кнопок используйте класс `sc-button--accent` вместе с существующими стилями геометрии и цвета.

Фон `#E44D1F`, существующее наведение `#FC7045`, анимация стрелки и видимый клавиатурный `outline` сохраняются. Тёмная CTA хедера сохраняет обычное оформление; правило убирает тень в её оранжевых состояниях. Тени карточек, иллюстраций, поверхностей и диалогов, белые кнопки карусели и другие элементы не входят в это правило.

Исходные объявления теней в замороженных CSS v62 оставлены побайтно: компонентный слой задаёт новую политику без `!important`. Не добавляйте glow через `box-shadow`, `filter: drop-shadow`, `text-shadow` или псевдоэлементы оранжевых кнопок.

Версии локальных библиотек: GSAP/ScrollTrigger 3.12.5, Lenis 1.3.26. Manrope 400/500/600 для оболочки и каталога хранится локально. На главной также сохранён Google Fonts `@import` из защищённого CSS v62, поэтому шрифты всего сайта нельзя считать полностью независимыми от сети.

## Как вносить изменения

Перед началом прочитайте [AGENTS](../AGENTS.md), проверьте текущую ветку и незавершённые изменения. Работайте в обычной отдельной ветке в основной папке. Новый worktree создаётся только с согласия владельца.

Старые папки `output/worktrees/site-v60` и `output/worktrees/works-v27` сохранены для сравнения. Они находятся в detached HEAD: это копии конкретных коммитов, а не ветки для новой работы. Не удаляйте и не перемещайте их без разрешения.

После правки выполните подходящие [проверки](QA.md) и откройте Pull Request. Не сливайте его и не публикуйте сайт без отдельного разрешения. Папку `output`, исходные ZIP и самостоятельные HTML-демонстрации в релиз не добавляйте.
