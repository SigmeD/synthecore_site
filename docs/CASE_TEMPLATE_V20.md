## Зафиксированная композиция

1. Общий Header из partials и фирменный фон. Первый экран: H1, вводный текст и коллаж из трёх экранов. На телефоне остаётся главный экран согласно v20.
2. Одна двухколоночная история: «Наш процесс» → «Результат» → «Интерфейсы». Три этапа с кругами 32 × 32 px, вертикальной линией и плавной сменой активности.
3. Справа общий CTA «Готовы обсудить вашу задачу»: H3 32 px, текст 16 px, кнопка 52 px. На ширинах от 1100 px CSS sticky сопровождает все три секции и заканчивается перед «Другими работами». До 1099 px баннер идёт в обычном потоке после истории.
4. Результат с главным экраном без дополнительной монолитной рамки. Четыре превью интерфейсов, две колонки на desktop и одна на телефоне. Увеличение открывает `dialog`; Escape, фон и кнопка закрывают его, фокус возвращается к выбранному превью. Уголковых кнопок увеличения нет.
5. «Другие работы»: пять проектов из актуального каталога, текущий исключён по `catalog_id`. Применяются его реальные карточки, тексты, изображения и модалки. Desktop показывает три карточки, до 1180 px две, до 650 px одну. Стрелки неподвижны на hover; доступны клик и горизонтальный touch. Клоны для циклической прокрутки скрыты от доступности и Tab.
6. Общий Footer из partials. Параллакс ограничен кейсом; GSAP не закрепляет баннер или футер. `prefers-reduced-motion` отключает параллакс и переходы, делает шаги читаемыми и оставляет нативную прокрутку.

Не менять без отдельного поручения порядок секций, геометрию, sticky-границу, цвета, типографическую иерархию, фон и движение. Manrope остаётся общим шрифтом. Основные тексты — 16 px, служебные подписи могут быть 11–14 px. На всех страницах действует общая политика кнопок без свечения; она не меняет цвета, геометрию, outline или движение стрелок.

## Как добавить следующий кейс

Скопируйте только JSON данных в `templates/data/cases/<slug>.json`. Для изображений используйте `assets/cases/<slug>/`; общие CTA-иллюстрации находятся в `assets/cases/shared/`. HTML-копии и отдельный CSS/JS без утверждённого варианта не создавайте: сборка сама выдаст `/raboty/<slug>/index.html`.

| Поля JSON | Правило заполнения |
|---|---|
| `slug`, `catalog_id` | URL и существующий ключ карточки. Beauty использует `beauty-insight` и `beauty`; остальные ключи перечислены ниже |
| `variant` | Отсутствие поля или `beauty-v20` сохраняет исходную композицию. `flowers-v2` и `metal-v5` — утверждённые варианты Flowers и Metal; неизвестные значения отклоняются |
| `status` | Честный статус результата; также используется в доступном названии основной области |
| `process` | Объекты `title` / `body`. В эталоне три этапа. Другое число требует согласования содержания и проверки композиции |
| `result` | Что сделали и получили, без фиктивных KPI и эффекта внедрения |
| `hero_media.left/main/right`, `result_media` | `src` от `/assets/` и содержательный `alt` |
| `screens` | Ровно четыре объекта `src`, `alt`, `caption`; исходный файл используется также для увеличения |

Тексты экранируются; ввод произвольного HTML не поддерживается. Сборка отклоняет некорректный slug, пустые обязательные поля, отсутствующие изображения и небезопасные пути. Карточки других работ извлекаются из `templates/pages/works.html`, отдельный список проектов не ведётся. Реестр JSON автоматически подключает готовый кейс на главной, в каталоге и в карусели других работ. Внешняя геометрия карточек не меняется.

### Единый источник названия и краткого описания

Название и описание карточки `/raboty/` — обязательный источник для карточек главной, H1 и вводного текста детальной страницы, модалок и «Других работ». Сборка читает их из `templates/pages/works.html` по `catalog_id`. SEO title получает то же название и суффикс SyntheCore, meta description — то же описание. JSON не должен содержать отдельные `short_name`, `h1`, `intro`, `meta_title`, `meta_description`; сборка отклоняет эти дубли.

Для Beauty везде используется «Управление студией красоты» и краткое описание из каталога. Отдельные названия «Beauty Insight AI» или «Центр управления…» не подставляются вместо него. Формулировки процесса и результата остаются индивидуальными. Чтобы поменять общий текст, сначала согласуйте и обновите каталог, затем выполните сборку и `node --test scripts/test-project-copy.cjs`. Тест проверяет все шесть работ и автоматическое обновление страниц при изменении каталога. Глобальное правило проекта закреплено в [AGENTS.md](../AGENTS.md#единые-названия-и-краткие-описания-работ).

Метки формата и тематики также берутся из двух плашек каталога, сначала синяя, затем зелёная. Главная и модалки показывают обе метки через ` · `, например «Прототип · Финансовая аналитика»; карточки каталога и «Других работ» сохраняют две плашки. Отдельные BeautyTech/CRM/E-commerce как категории главной не поддерживаются. Изменение меток каталога автоматически обновляет зависимые строки при сборке.

| Следующий проект / ключ каталога | Что подтвердить до наполнения |
|---|---|
| B2B-кабинет / `b2b` | Реализованный объём, этапы, итог и экраны |
| Кастомная CRM / `crm` | Реализованные функции и подтверждённый результат |
| «Простор» / `prostor` | Прототип интерфейса, дизайн-концепт; не действующий магазин |

Beauty, Flowers и Metal созданы; три остальные работы пока используют модалки. Владелец последовательно разрешил слияние PR #13 и PR #12. [Совместная приёмка](qa/case-integration/README.md) проверяет сохранность всех трёх полных страниц после точной отмены добавленных ссылок в «Других работах». Если материалов не хватает, перечислите недостающее и согласуйте упрощение до создания публичного кейса. Не подменяйте реальные экраны генерацией и не копируйте этапы Beauty как факты другого проекта. Все цифры интерфейсов Beauty демонстрационные, это не результаты внедрения.

## Утверждённый вариант Metal v5

Поручение от 23 октября 2026: `/raboty/metal-calc/`, источник `SyntheCore_Metal_Calculator_Detail_v5.zip`. [Проверки и сравнение с v5](qa/metal-v5/README.md), [SHA исходников и изображений](qa/metal-v5/source-audit.json).

В общем каркасе выбираются два partial: `hero-metal.html` вместо коллажа и `result-metal.html` вместо экрана результата. Один центральный скрин показывается полностью через `object-fit: contain`; в `hero_media` допускается только `main`. В `process` ровно пять этапов, в `screens` — четыре интерфейса. `result_media` не используется; `result_metric` содержит `value`, `label`, `aria_label`, `art`. Показатель «−50% времени на расчёт стоимости изделий» предоставлен владельцем в задании и архиве; метод измерения в исходниках не указан, независимая оценка эффекта не проводилась.

Два специфических CSS v5 объединены в `case-metal.css` под `body.sc-case-metal`; общий `case-detail.css` и весь JS сохранены. В reduced motion центральный скрин остаётся видимым без анимации: в автономном исходнике он скрывался из-за сочетания `opacity: 0` и отключённой анимации. Header/Footer, CTA, sticky, lightbox и карусель используют действующие компоненты и одного владельца Lenis.

После локального просмотра владелец 23 октября уточнил композицию первого экрана: убрать тень и белые боковые поля рамки. Контейнер скрина теперь прозрачен, без обводки и тени; само изображение центрируется в естественных пропорциях со скруглением по его границам. Размеры сцены и параметры движения сохранены. Приложенный `SyntheCore_Metal_Calculator_Detail_v4_preview.html` использован для сравнения композиции; его три карточки и старые скриншоты не переносятся вместо согласованного одного полного экрана v5.

Название, краткое описание и метки Metal, как и Beauty, берутся из каталога. Это сохраняет ранее утверждённую синхронизацию вместо альтернативного вводного текста автономной v5. Остальные пять карточек каталога не меняются; в Beauty меняется только ссылка Metal внутри «Других работ». Вариант v5 не разрешает менять композицию Beauty или будущих кейсов без поручения.

## Утверждённый вариант Flowers v2

Поручение от 23 октября 2026: `/raboty/flowers/`, источник `SyntheCore_Flowers_Detail_v2.zip` и MD-задание интеграции. [Проверки и сравнительные снимки](qa/flowers-v2/README.md), [SHA исходников и изображений](qa/flowers-v2/source-audit.json).

В общем каркасе выбираются `hero-flowers.html` и `result-flowers.html`: три CSS-рамки смартфонов Home / Catalog / Profile с выделенным центральным каталогом, затем два устройства результата. На телефоне смартфоны прокручиваются по горизонтали нативно, как в v2. Градиентное растворение нижней части композиции и окна просмотра длинных экранов сохранены из эталона. Полные исходные изображения доступны в lightbox; превью не растягиваются и не заменяются генерацией.

В `hero_media` ровно три объекта `left`, `main`, `right`; `process` содержит четыре утверждённых этапа, `screens` — Главная, Каталог, Поиск, Профиль. `result_media` для этого варианта не нужен: результат использует уже зарегистрированные Home/Catalog. Копируются только четыре WebP в `assets/cases/flowers/`. Ширина и высота экранов не предполагаются одинаковыми: Поиск имеет исходные 780 × 868 px, остальные экраны — высоту 2048 px.

Специфический `detail-flowers.css` перенесён в `case-flowers.css` под `body.sc-case-flowers`, имя keyframes получило префикс. Общие CSS/JS, Header/Footer, CTA, версии библиотек, sticky и параллакс не меняются. Цветочная композиция не добавляет `.case-hero__figure`: она использует собственные рамки/вход из v2; существующий JS продолжает обслуживать историю, галерею, lightbox и карусель. Default Beauty сохранён побайтно после отмены одной новой ссылки Flowers в «Других работах».

Статус результата — UX/UI-концепт и интерактивный прототип. Не заявлять выпущенное PWA, MVP или релиз Android/iOS. 80% покупок со смартфонов — данные со слов заказчика, приведённые на этапе анализа; не показатель нашей работы. Название, вводный текст и обе метки берутся из каталога по общему правилу, поэтому отличаются от автономного заголовка/вводного текста v2. Отдельные названия и новые числовые результаты не добавляются.

## Ссылки и границы изменений

Для готового кейса вся работа на главной и вся карточка каталога, включая изображение, заголовок и «Смотреть проект», ведут прямо на детальную страницу. Отдельная малозаметная ссылка или модалка вместо основного перехода не допускаются. Это общее правило для Beauty и следующих пяти работ, закреплённое также в [AGENTS.md](../AGENTS.md#переходы-к-детальным-работам).

Маршруты берутся из JSON: добавление следующего фактического кейса и запуск сборки автоматически подключают его ссылки. Используются настоящие `a[href]`, доступные с клавиатуры и для открытия в новой вкладке. Модальный обработчик обслуживает только `button.case-card__open`. Три работы без детальных страниц сохраняют модалки; несуществующих URL нет. Геометрия сцен и карточек не меняется.

Новая [политика ссылок](../css/case-links.css) задаёт только кликабельную область внутри существующего frame. [QA-исключение](../scripts/lib/approved-case-links.cjs) отменяет точные ссылки зарегистрированных кейсов и единственное уточнение селектора модалок перед сравнением с прежними SHA. Перенос ссылки в Header/Footer, дубли и другие изменения отклоняются тестами. Исходные manifests не переписаны; 17 motion-файлов и partials сохранены побайтно. Отдельная политика отсутствия свечения также проверяется точным исключением, утверждённым 22 октября.

Перед сдачей каждого кейса выполните `node scripts/verify-case-links-browser.cjs`: нужны реальные клики по изображению/названию/CTA, Enter и Ctrl/Cmd-клик, обычное движение и reduced motion на desktop/mobile. По умолчанию проверяется Beauty; для Flowers или Metal задайте `$env:CASE_PROJECT = 'flowers'` или `'metal'`. Проверка только существования ссылки недостаточна. Для нового кейса укажите его `catalog_id`; общий механизм переходов сохраняется.

На слияние PR #10 и PR #11 от 23 октября 2026 получены отдельные разрешения владельца. После подготовки Flowers владелец отдельно поручил выполнить слияние PR #13 и git push. После этого владелец отдельно поручил слияние Metal PR #12 и git push. Оба разрешения относятся только к своим PR; будущие PR и публикация требуют отдельных разрешений. Остальные кейсы добавляются по отдельным поручениям с фактическими материалами.
