# SyntheCore v62 — перенос новой анимации из локальной сборки в Git

**Критически важно: в Git может находиться более старая реализация анимаций (ориентировочно v60). Владелец утвердил НЕ её, а реализацию v62 из данного ZIP.** Текущее состояние удалённого Git до начала работы агенту нужно проверить: версия в `main` здесь не проверялась.

## 1. Единственный источник истины

**Эталон:** `SyntheCore_v62_Git_Agent_Handoff_v2.zip`, содержащий полностью рабочие исходные `index.html`, `css/`, `js/`, `assets/`, скрипты проверки и документацию. Это НЕ патч только с текстами; ZIP содержит новую, последовательно доработанную анимацию.

При миграции:

1. Исходная v62 имеет приоритет над старыми HTML, JS, CSS, настройками анимации и библиотеками из Git.
2. **Разрешено и обязательно заменить** в Git старые анимационные файлы соответствующими файлами из ZIP v62, сохранив их байт-в-байт. При этом запрет на «изменение анимации» означает: НЕ менять уже утверждённые файлы v62 по своей инициативе. Он НЕ означает сохранение старого поведения Git.
3. Не делать `git checkout -- js/ css/` из прежней версии после импорта; не брать старые `js/hero-scroll.js`, `js/works.js`, `js/services.js`, `js/testimonials.js`, `css/sticky-handoff-v61.css` из существующего Git.
4. Не переносить только `index.html`/типографику и не копировать старый CSS поверх v62: это вернёт прежние резкие фиксации.
5. Текущие хедер и футер в финальном дереве также должны совпасть с эталоном v62. **После точного переноса** обе области полностью закрыты для дальнейшего редактирования. Если старая версия Git содержит отличия, зафиксировать их как разницу импорта, а не сохранять старую шапку или футер по умолчанию.
6. Если в Git есть более поздние несогласованные изменения, нельзя молча затирать их: показать конфликт и дождаться решения владельца.

## 3. Список защищённых файлов и проверки

Реестр **17 CSS/JS-файлов** со значениями SHA-256 — в `docs/V62_SOURCE_SHA256.json` → `motion_lock`. Среди них:

- `js/hero-scroll.js`, `js/hero-geometry.js`, `js/works.js`, `js/services.js`, `js/process.js`, `js/testimonials.js`, `js/main.js`, `js/faq-footer.js`;
- `css/sticky-handoff-v61.css`, `css/v62-services-alignment.css`, `css/works.css`, `css/services.css`, `css/process.css`, `css/testimonials.css`, `css/main.css`, `css/faq-footer.css`, `css/design-system-v61.css`.

Это полный список (8 JS + 9 CSS = 17). Помимо них, для точного импорта необходимо перенести утверждённый `index.html`, CSS-надстройки типографики, локальные библиотеки GSAP/Lenis и исходные ассеты из v62. **Нельзя полагаться только на контроль 17 файлов:** неправильный порядок подключения CSS/JS или старая разметка тоже сломают анимацию.

После переноса выполнить из корня репозитория:

```bash
node scripts/verify-v62-import.cjs --strict
node scripts/check-project.cjs
node scripts/verify-works-static.cjs
node scripts/verify-services-static.cjs
node scripts/check-hero-geometry.cjs
node --test scripts/test-static-checks.cjs
```

`--strict` сравнивает 437 исходных файлов эталонной сборки (включая **полный `index.html`**, CSS, JS и локальные библиотеки). Добавленные в v2 документационные файлы не входят в исторический список, это ожидаемо. Если текущий Git требует сохранить отличающиеся инфраструктурные файлы или другие уже согласованные изменения, **не объявлять strict-проверку пройденной**: зафиксировать список и согласовать расхождения.

Для последующих правок только контента используйте `node scripts/verify-v62-import.cjs` — контроль 17 зафиксированных файлов. Отдельно проверить, что не изменены шапка/футер, в т.ч. через селекторы и CSS-каскад.

## 4. Проверка именно анимации в DevTools и браузере

На десктопе (например, 1440 × 900) последовательно проверить:

1. **Hero:** при медленном и быстром прокручивании фото плавно расширяется; переход в «С кем работаем» не показывает пустую остановку.
2. **«Наши работы»:** первая карточка входит в сцену с масштабированием; шесть карточек листаются вперёд и назад без скачка. При закреплении нет трёх старых GSAP `pin-spacer` (Hero/Works/Services) — эти сцены работают через CSS `sticky` в предусмотренном режиме.
3. **«Что мы делаем»:** при старте горизонтали полностью видна карточка №1; `sc-services__viewport.scrollLeft === 0` в закреплённом состоянии. Заголовок и первая карточка выровнены по одному левому краю. В конце достигается последняя карточка; после выхода нет рывка.
4. **Отзывы:** карточки проходят плавно и не слишком быстро; расстояние сцены на десктопе определяется финальным CSS (`height:533svh;min-height:3770px`) и зависит от фактической высоты viewport. Не подменять его старым +50%.
5. **Адаптивы:** 320, 390, 768, 1024, 1440, 1920 px; переход десктоп ↔ планшет ↔ мобильный без дублей триггеров/переполнения, мобильный горизонтальный свайп услуг работает.
6. `prefers-reduced-motion`: анимации корректно упрощаются; нет ошибок в консоли.

Для выявления рывков использовать `QA/DEVTOOLS_STICKY_TRACE.js` из ZIP. В отчёт включить **фактические** наблюдения и скриншоты. Отсутствие runtime-ошибок само по себе не доказывает визуальную плавность: нужна ручная проверка реальным колесом мыши/тачпадом.

## 5. Git-процесс и ограничения

1. Проверить репозиторий (`git status`, ветки, `git remote -v`, историю, состояние актуального `main`) и показать план замены старой реализации.
2. Создать отдельную ветку от актуального `main` (`chore/import-approved-v62` или аналог). Никаких force push / rewrite history.
3. Сверить файловый diff старой Git-версии с v62, затем импортировать файлы как **согласованную базу**. Не копировать `.git` из ZIP и не выполнять слепой `rm -rf`.
4. Сначала проверить exact SHA + `--strict`, затем тесты и визуальный прогон, только потом создать PR. При конфликтах остановиться.
5. В PR отдельно указать: **«Старая анимационная реализация Git заменена утверждённой v62 из приложенного архива. Сами файлы v62 не изменялись; контрольные суммы совпадают»**. Если старую версию в Git не удалось установить, написать, что сравнение не выполнено, а не выдавать предположение за факт.
6. Не делать merge, deploy и публикацию без согласования.

## 6. Что остаётся заморожено после импорта

Хедер (`#floatingHeader`), футер (`#contact.sc-footer`) и вся утверждённая анимация v62. Для будущих задач допускаются только **отдельно поставленные** изменения текстов/шрифтов/контентных изображений в остальных секциях. Любое вмешательство в motion-файлы, геометрию sticky-сцен, настройки Lenis, GSAP, ScrollTrigger или длительности требует прямого разрешения владельца.
