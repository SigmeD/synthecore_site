# SyntheCore — анимации v61: аудит и безопасный рефакторинг

**Основа:** обновлённая v60 из Git, экспериментальная v61 с дизайн-системой v0.2.  
**Статус:** кандидат для визуальной приёмки, GitHub и production не изменены.  
**Граница задачи:** футер, SVG-волны, тексты, иллюстрации, цвета, верстка и порядок секций не менялись.

## Что обнаружено и исправлено

| Модуль | До | После | Почему |
|---|---|---|---|
| `js/works.js` | Ветвление на 480/850px происходило лишь при построении временной шкалы; `resize` вызывал `refresh` | MediaQuery `change` пересоздаёт только сцену Works при переходе через 480/850px | Чтобы tween оформления карточки не оставался от другого адаптива |
| `js/services.js` | Возможны дублирующие `refresh()` из `resize`, `matchMedia`, `load`; не использовался `resizeObserver` | Объединение обновлений в один `requestAnimationFrame`, наблюдение за шириной галереи, восстановление сцены при появлении/исчезновении переполнения | Уменьшить дорогие геометрические пересчёты и исключить застарелую ширину |
| `js/testimonials.js` | Формула расположения дублировалась в `draw()` и обработке клавиатуры; `offsetHeight` читался для каждой карточки при каждом кадре | Единая геометрия, кэш размеров на `setup`/`refresh`, единые именованные параметры движения | Одинаковые координаты при прокрутке и клавиатуре, меньше layout reads |
| `js/process.js` | Прогресс рассчитывался `index/2` | `index/Math.max(1, steps.length - 1)` | Фактическое число шагов вместо жёсткой константы |
| `js/hero-scroll.js` | Числовые коэффициенты появления Audiences разбросаны по функции | Вынесены в объект settings, итоговые значения не изменены | Прозрачность настроек без изменения сложной hero-сцены |

## Не изменено намеренно

- Lenis остаётся **единственным** экземпляром и владельцем плавного скролла в `hero-scroll.js`.
- ScrollTrigger-пины, их очередность, длительности и привычное визуальное движение сохранены.
- Движение карточек Works, Services и Testimonials не заменено механикой Roveia: до утверждения новой motion-системы копирование эффектов было бы изменением дизайна.
- `js/faq-footer.js`, `css/faq-footer.css`, волны и футер не затронуты.
- Исходные RGB-массивы в Hero — это явная палитра перехода текста над раскрываемым изображением, **не случайный хардкод**. Вынос в общие CSS токены требует отдельного теста на контраст.
- Пропорции движения отзывов специально заданы коэффициентами от viewport и сохранены численно.

## Оставшиеся риски

1. `hero-scroll.js` комбинирует Lenis, clip-path и покадровое обновление градиентов текста. Полное разделение на модули нужно делать отдельно с замерами производительности и пиксельным сравнением.
2. Работа `ScrollTrigger.refresh` при одновременном открытии FAQ и переходах между breakpoint-ами требует браузерной регрессии.
3. Демонстрационные отзывы нельзя выдавать за реальные.
4. Motion Roveia — референс, а не точный алгоритм SyntheCore: перенос новых анимаций требует отдельного визуального согласования.
