# SyntheCore v38 — исправление перехода Works → Services

**База:** утверждённая версия v37. Изменения ограничены переходом после шестой работы и внешними тенями карточек Works. Никакие изображения, заголовки, карточки или алгоритмы движения по горизонтали не переделывались.

## Воспроизведённая причина

1. Все шесть `.sc-work-frame` имели внешний `box-shadow`. При CSS `position: sticky` тени под перекрывающимися карточками визуально складывались и давали толстую тёмную полосу под последней карточкой.
2. Высота последнего `.sc-work-item` составляла `145svh`, тогда как видимый кадр был существенно ниже. Чтобы искусственно убрать пустое место, у `.sc-services` стоял отрицательный `margin-top:-75svh` (на узких экранах — `-55svh`). GSAP переносил его на `pin-spacer`; возникало реальное перекрытие двух секций в потоке.

## Решение

- **CSS Works:** последнему `.sc-work-item:last-child` назначена высота `works-height + 2 * works-padding` вместо полной высоты `works-step`. Остальные пять `sc-work-item`, их размеры и анимации не менялись. Прежний `--works-last-hold:85svh` сохранён — последняя работа по-прежнему задерживается и уходит вверх.
- **CSS Services:** `margin-top:0` во всех режимах. Секция размещается сразу после Works в нормальном документном потоке. `ScrollTrigger pin`, анимация входа и horizontal track продолжают работать.
- **Тени Works:** в базовой `.sc-work-frame` отключён внешний `box-shadow`; он включён только для `.sc-work-item--front .sc-work-frame`, с единым умеренным значением. Это предотвращает накопление теней от уже перекрытых карточек.
- **JS Works:** функция `updateFrontCard()` использует существующие GSAP `onUpdate`, выбирая передний видимый кадр по его положению. Новых `ScrollTrigger`, `scroll`-обработчиков, Lenis и перехвата колеса не добавлено.
- **Reduced motion:** специальное правило возвращает последний элемент к обычной высоте и потоку; отключение pin/services остаётся прежним.

## Контрольные размеры

| Режим | Стык Works/Services | Отрицательный margin | Переполнение страницы | Ошибки JS |
|---|---:|---:|---:|---:|
| 1440 × 900 | 0 px | нет | нет | нет |
| 1920 × 1080 | 0 px | нет | нет | нет |
| 768 × 1024 | 0 px | нет | нет | нет |
| 390 × 844 | 0 px | нет | нет | нет |
| 320 × 700 | 0 px | нет | нет | нет |
| 1440 × 900, reduced motion | 0 px | нет | нет | нет |

На desktop проверены этапы «последняя работа», «вход услуг», начало закрепления, середина, конец и прокрутка обратно. GSAP создает `pin-spacer` — это нормальная часть существующей анимации. Переход больше не зависит от отрицательного margin.

**Особенность:** на мобильных используется нативная горизонтальная лента с прокруткой свайпом и стрелками; GSAP pin не создается. На реальных телефонах, в Safari и в production новый код пока не тестировался — эти проверки нужны перед публикацией.
