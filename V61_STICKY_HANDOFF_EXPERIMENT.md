# SyntheCore v61 — эксперимент «переход без остановки»

**Статус:** отдельный эксперимент. НЕ утверждено, в GitHub/production ничего не отправлено.

## Источники и наблюдения

- Референс Roveia: `bandicam 2026-10-20 13-29-39-537.mp4`, 73,99 с, 3800×1944, 30 FPS. На ~8–12 сек контент «Who We Work With» выходит вслед за Hero; ~36–42 сек последовательность кейсов сменяется карточками услуг без отдельной паузы. Съёмка показывает визуальное поведение, но не позволяет утверждать, что все компоненты Roveia реализованы через `position:sticky`.
- SyntheCore: `bandicam 2026-10-20 14-29-25-204.mp4`, 55,3 с. Пользователь указал на отдельные остановки/рывки между Hero/Audiences, Works, Services.
- В исходном v61 Hero завершал расширение фотографии при `5/6` собственной scroll-дистанции, оставляя последние ~16,7% закреплённого участка без заметного изменения фотографии. На 1440×900 это ≈165 px скролла.
- В Works первая карточка завершала `ease:sine.inOut` ровно в начале закрепления: скорость масштаба стремилась к 0, затем стартовало движение следующей карточки. Services также запускали горизонтальную анимацию с `sine.inOut` (нулевая стартовая скорость).
- У отзывов ранее использовался CSS sticky без GSAP `pin-spacer`, и пользователь отметил более плавный переход. Это послужило основанием для **эксперимента**, а не доказательством, что sticky автоматически обеспечивает нужный визуальный результат.

## Что изменено

| Файл | Правка |
| --- | --- |
| `css/sticky-handoff-v61.css` | Новый ограниченный по классам экспериментальный слой: CSS sticky для Hero, Works и Services. Базовые стили и футер не изменены. |
| `js/hero-scroll.js` | Вместо GSAP `pin:true` высота сцены выставляется CSS; GSAP отвечает за clip/scale/цвет. Раскрытие фотографии занимает **100%** scroll-дистанции вместо 5/6, исключая пустой остаток. |
| `js/works.js` | Вместо GSAP `pin:true` sticky stack с высотой из текущего числа карточек. Масштаб первой карточки на входе `ease:none`; вертикальный вход следующих карточек начинается сразу (`ease:none`). Остальные параметры/масштабы сохранены. |
| `js/services.js` | Вместо GSAP `pin:true` sticky scene; горизонтальная галерея следует `scroll` линейно (`ease:none`) без торможения в начале и конце. |
| `css/testimonials.css` | **533svh, min-height:3770px**, что составляет +30% к исходным 410svh/2900px, а НЕ +50%. |
| `js/testimonials.js` | Время сглаживания возвращено к **0,18 с** вместо 0,24 с. |
| `index.html` | Подключает новый CSS-слой последним для A/B-эксперимента. |

Футер, волны, контент, изображения, дизайн-система v61, файлы GSAP и Lenis НЕ изменены. Сценарий без JS и `prefers-reduced-motion` сохраняет обычную страницу.

## Проверки

- Полностью автономная HTML-сборка, Chromium; **1440×900, 1024×768, 390×844, 320×568**, плюс **1440×900 prefers-reduced-motion**: 0 runtime JavaScript exceptions, 0 горизонтального переполнения.
- Вместо 3 активных GSAP `pin` триггеров на десктопе теперь **0**; `ScrollTrigger` продолжает считать progress. Для мобильного Hero/Services применяются исходные fallback-режимы.
- При точной прокрутке на ±2px вокруг `start`/`end` Works и Services sticky position непрерывен; на входе `top` достигает 0 и не прыгает, на выходе уходит на −2px, затем −4px. Переходы назад сохраняют геометрию.
- Переход адаптивов на одной странице: **1440→840→390→1024→1440**; нет JS-ошибок, переполнения или оставшихся GSAP pin-spacer.
- Статические тесты `node --test scripts/test-static-checks.cjs`: **69/69 PASS**; `check-project.cjs`, `verify-works-static.cjs`, `verify-services-static.cjs`, `check-hero-geometry.cjs`: PASS.
- Исторический тест `verify-works-timeline-v43.cjs` **неприменим** к v61: он требует только один ScrollTrigger, тогда как уже в предыдущем v61 имеются отдельные entry+stage триггеры, а текущий эксперимент сознательно убирает GSAP `pin`. Его нельзя считать тестом новой архитектуры.

## Что НЕ подтверждено

Проверки геометрии и DOM не доказывают, что пользователь больше не почувствует «стоп → дальше». При sticky сам блок всё равно удерживается, а движения карточек подчинены прокрутке. Важна проверка реальной мышью/тачпадом и частотой экрана. Параметры движения и длину скролла ещё не согласовали.

## Диагностика в DevTools

В Chrome → DevTools → Console вставить `QA/DEVTOOLS_STICKY_TRACE.js`, быстро и медленно прокрутить Hero→Audiences, Works и Services, потом выполнить:

```
SCT_TRACE.stop();
SCT_TRACE.report();
```

Функция вернёт кадры и показания scrollY/скорости/координат сцены/ScrollTrigger. Исходники для сравнения — предыдущий кандидат `SyntheCore_v61_PinBridge_Standalone.html`.
