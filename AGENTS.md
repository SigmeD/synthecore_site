## КРИТИЧЕСКОЕ УТОЧНЕНИЕ: АНИМАЦИЯ ИЗ GIT УСТАРЕЛА / НЕ ПОДТВЕРЖДЕНА

Не сохраняй старую анимацию из репозитория по формулировке «анимации не менять». **При интеграции требуется импортировать текущую утверждённую анимационную реализацию v62 из данного архива**, даже если это меняет существующие JS/CSS в Git. После импорта содержимое 17 защищённых файлов v62 нельзя менять ни на байт. Подробности — `docs/V62_ANIMATION_MIGRATION_GUIDE.md`.

Возможная старая версия в `main` (исторически v60) — гипотеза до фактической проверки Git. Действительное состояние удалённого репозитория сначала проверить.

## Источник истины

Последняя согласованная **локальная v62** из пакета передачи. `BUILD_V62.md`, старый `README.md`, отчёты V60/V61 описывают исторические состояния, а не автоматически актуальный Git. Первичная задача — безопасная интеграция v62, не самостоятельное изменение дизайна.

## Жёсткий запрет без отдельного разрешения владельца

- **Хедер**: весь `header.floating-header` (`#floatingHeader`), меню, логотип, кнопка, любые его CSS/JS/тексты/адаптивы.
- **Футер**: весь `section.sc-footer#contact`, включая CTA, навигацию, волну и связанную разметку/стили/скрипты.
- **Анимации**: Lenis/GSAP/ScrollTrigger, CSS `sticky`, `pin`, `scrub`, `lerp`, `ease`, таймлайны, отзывные карточки в движении, параметры входа/выхода секций, прокрутка, ширина/высота scroll-сцен, `overflow: clip`, начало и конец горизонтальных галерей и межблочные отступы, согласованные с механикой.
- Запрещены: автоматический рефакторинг JS/CSS-анимаций, глобальная нормализация селекторов, удаление скрытых элементов, к которым обращается скрипт, `npm update` или замена библиотек «для порядка», изменение файлов из protected SHA-256 manifest.

**Защищённые 17 файлов перечислены в** `docs/V62_SOURCE_SHA256.json`. Они могут быть перенесены из эталона в Git без модификаций. `css/faq-footer.css` и `js/faq-footer.js` защищены целиком, даже если внутри есть логика FAQ. Правки FAQ оформлять отдельно, не меняя этот код.

## Git

Работать в отдельной ветке и через Pull Request; не делать прямой push в `main`, не выполнять merge/deploy автоматически. Сначала обнаружить текущее состояние Git — не считать, что опубликована v62. Не импортировать архив `.zip` и автономную HTML-демонстрацию в исходники Git как релизные файлы.

## QA

Команды см. `TASK_FOR_GIT_AGENT_V62.md`. Зафиксировать SHA-256 protected файлов, сравнительные скриншоты на десктопе/мобильном, работу быстрого/обратного скролла и адаптивов. При сомнении не изменять анимации, а передать проблему владельцу.
